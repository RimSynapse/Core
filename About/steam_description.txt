[h1]RimSynapse - Core[/h1]
[b][url=https://github.com/RimSynapse/Core/wiki]Official Wiki and Documentation[/url][/b]
[b]The foundational Large Language Model (LLM) connector and narrative intelligence engine for RimWorld.[/b]

RimSynapse Core is a powerful, asynchronous background engine that natively connects RimWorld to local Large Language Models (LLMs). It acts as the central brain of the RimSynapse ecosystem, automatically intercepting vanilla game events and orchestrating them into rich, cohesive story arcs.

[h1]🔥 New Feature: LLM Direct Action Console[/h1]
[b]Tired of memorizing complex dev console codes? Just say what you want in plain English![/b]

The LLM Direct Action Console acts as an AI-powered command center. You simply open the console, type what you want in plain English, and the Storyteller LLM acts as an active agent to compile, translate, and execute native in-game tool calls automatically in real-time.

[b]Example Command Input:[/b] [i]"Make Fred have 20 Shooting, remove the Bipolar trait from Sarah, and start a fire on the solar generator."[/i]

[b]How it works:[/b]

[b]Type in plain English:[/b] State your desires, scripts, or debug requests naturally.
[b]AI Translation:[/b] The storyteller parses your input, mapping it to real C# game methods (modifying pawn skills, altering traits, spawning disasters, adjusting weather, etc.).
[b]Instant Execution:[/b] The commands run natively on the active tick without breaking immersion.

[h2]Key Features[/h2]
[list]
[*] [b]LLM Direct Action Console (Command in Plain English!):[/b] Control the game world using natural language! Open the Direct Action Console, type what you want in plain English (e.g. [i]"Make Fred have 20 Shooting, remove the Bipolar trait from Sarah, and start a fire on the solar generator"[/i]), and watch the Storyteller LLM act as an active agent, translating your request into native in-game tool calls and executing them in real-time!
[*] [b]Universal Backend Support:[/b] Connects natively to LM Studio, Ollama, or any OpenAI-compatible local API (e.g. OpenRouter, LocalAI) without complex setups.
[*] [b]Background Threading:[/b] Never drops a frame. All LLM requests are queued, processed, and sanitized asynchronously on separate threads.
[*] [b]Dynamic Priority Queue:[/b] Intelligently manages hundreds of requests with an advanced Linux-style top-monitor queue system, prioritizing critical events and starving obsolete prompts.
[*] [b]Auto-Discovery and Keep-Alive:[/b] Automatically detects active models and manages keep-alive pings to ensure your LLMs don't go to sleep.
[*] [b]Event Tracking Ledger:[/b] Snapshots colony wealth, nutrition, and colonist status chronologically when events trigger, feeding the AI perfect narrative context.
[*] [b]Faction Perception Tracking:[/b] Factions dynamically adjust their subjective perception of your wealth and strength through visits and trade.
[*] [b]Colony Snapshots:[/b] Captures snapshots of the colony's mood, health, and stats when events occur to provide rich context.
[*] [b]Memory Infrastructure:[/b] Provides the per-pawn memory bank, weighted tag system, and decay engine used by companion mods to give colonists persistent, evolving memories.
[*] [b]Opportunistic Task Scheduling:[/b] A background task manager that feeds low-priority LLM requests (backstory generation, memory creation) into idle GPU cycles without impacting gameplay performance.
[/list]

[h2]Changelog (v0.6.0) - Agent and Tool Foundation[/h2]
[b]The storyteller can now plan and carry out multi-step work on its own - and it is built to stay fast on modest hardware.[/b]

[b]The agent[/b]
[list]
[*] [b]NEW - Multi-step plans that wait on the game:[/b] The agent composes scripts that call game tools, pause until something is true (a pawn reaches a spot, picks up a weapon, goes down), see what happened, and keep going. No more one-shot commands that fail because the pawn had not arrived yet.
[*] [b]NEW - Scripts survive saving and loading:[/b] A plan waiting on a game condition picks up where it left off after a reload, with its timeout re-anchored so it does not instantly give up.
[*] [b]NEW - Run controls:[/b] Turn limits, a per-run request budget, and a stop button. Nothing can spiral.
[*] [b]NEW - Autonomous actions are gated:[/b] Anything the agent does on its own initiative cannot change your colony unless you switch on "Allow autonomous mutations". Your own commands are unaffected.
[*] [b]NEW - The storyteller escalates when reality surprises it:[/b] When a scripted feature hits something it was never taught to handle, it hands the situation to the agent instead of quietly giving up. Off by default, rate-limited when on.
[*] [b]NEW - Agent Runs inspector:[/b] The Script Debugger now shows what the agent decided each turn, what it ran, what came back, what it cost, and lets you cancel a run.
[*] [b]FIXED - Silent failures:[/b] A mistyped tool used to look like a success, and a malformed plan was dropped with nothing in the log. Both are now reported plainly.
[/list]

[b]Speed and small hardware[/b]
[list]
[*] [b]NEW - It measures your setup instead of guessing:[/b] Core times real end-to-end responses and picks a capability tier from the evidence - starting conservative, scaling up only when your machine proves it can, and stepping back down the moment responses slow.
[*] [b]NEW - Designed down to a 2k context window:[/b] The agent is told about the handful of tools your request actually needs, and can search for the rest mid-conversation. A vague request now produces the smallest prompt instead of the largest.
[*] [b]NEW - Faster answers:[/b] Obviously-useful lookups run before the first request and are included up front, so simple requests often finish in one round trip instead of two. Large results travel as a short excerpt the model can expand on demand.
[*] [b]NEW - Conversations get priority:[/b] Colonist dialogue aims for under half a second. Background work (like nightly reviews) sizes itself to finish inside the in-game night, learns which hours are usually quiet, and always yields to whatever you are doing.
[*] [b]NEW - Cloud API cost control:[/b] Cloud providers are treated as pay-per-token by default and budgeted accordingly, with an experimental toggle to ignore cost and simply go as rich as latency allows.
[/list]

[h2]Requirements and Setup[/h2]
[list]
[*] Harmony
[*] A local LLM server (like LM Studio or Ollama). We recommend 8B+ parameter models.
[*] [b]IMPORTANT: Reasoning Models (DeepSeek-R1, Gemma-QAT, etc.):[/b] These models generate internal "chain-of-thought" (reasoning) tokens before outputting the final response. This can add significant latency (30-40 seconds per request) on local setups.
[list]
[*] [b]To disable thinking in LM Studio:[/b] Go to the "My Models" tab, select your active model, and in the right-hand "Inference Settings" panel, toggle "Enable Thinking" to OFF.
[*] [b]To disable thinking in Ollama and vLLM:[/b] Check the "Disable thinking/reasoning" option under RimSynapse Core settings in-game.
[*] For the fastest, instant responses (2-3 seconds), we recommend using standard non-reasoning "Instruct" models (such as gemma-2-9b-it or llama-3-8b-instruct).
[/list]
[/list]
